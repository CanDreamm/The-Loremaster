# @publikot_bot через Chatbot и webhook

UUID бота: `5409db73-f74b-4095-aaa4-a2341a4a87db`.
API: `https://chatbot.hopop.ru/api/v1`. Токен BotFather не используется;
все Telegram-методы вызываются через сервис. Входящие события — стандартный Telegram Update.

## Что реализовано

`BOT_TRANSPORT=telegram` запускает локальный HTTP-обработчик webhook вместо
VK Long Poll. Общая логика Публикота поддерживает меню, проекты, доступ участников,
настройки, промпты, генерацию текста, исправления и публикацию в ВК после подтверждения.
Кнопки преобразуются в Telegram inline keyboard; короткие токены хранятся в SQLite
и привязаны к получателю. Поддерживаются только личные чаты.

Telegram использует отдельную `data/publikot-telegram.sqlite3`. Пользователи,
назначения и проекты из базы ВК автоматически не переносятся. Администратор —
`OWNER_TELEGRAM_ID`, не `OWNER_VK_ID`. Авторизация ВК привязывается через одноразовый
OAuth state к инициатору Telegram; аккаунт ВК проверяется отдельно вместе с правами
на публикации и выбранные сообщества.

Webhook подтверждается HTTP 200 после сохранения события в SQLite. Один обработчик
выполняет события последовательно; повторный update_id не повторяет действие.
Ожидающие события переживают перезапуск. События, прерванные во время выполнения,
помечаются failed без автоматического повтора внешних операций. Проверьте /status
и стену ВК перед новой командой. Готовые тела входящих событий удаляются из очереди.
Отправки через сервис получают отдельный Idempotency-Key; автоматических повторов нет.

## 1. Настройки на сервере

Обновите код по [инструкции обновления](server-update.md), сохранив .env.python
и данные. Остановите текущий экземпляр бота: ВК и Telegram в этой конфигурации
используют один порт 8081 и запускаются по очереди. Не запускайте две службы.

Из каталога проекта, обычно `/opt/publikot`:

```sh
.venv/bin/python scripts/configure-telegram.py
.venv/bin/python -m publikot --check
```

Скрипт спрашивает API-ключ скрытым вводом, сохраняет UUID, транспорт, Telegram ID,
генерирует секрет webhook. Существующие настройки не удаляются; права .env.python — 600.
Он сохраняет текущую настройку OAuth или добавляет приложение 54825715 и
https://bot.itiscat.ru. OAuth callback остаётся `https://bot.itiscat.ru/oauth/vk/callback`.
Доступность приложения и права wall/photos/groups проверяются отдельно.
Секреты не отправляйте в чат, Git или скриншоты.

Если свой Telegram ID неизвестен, оставьте его пустым и временно запустите:

```sh
.venv/bin/python -m publikot --identify
```

Этот режим слушает webhook, пока вы не остановите процесс. Настройте nginx
и webhook по следующим разделам, отправьте `/id` в @publikot_bot.
Ответ покажет ваш ID; доступ администратора автоматически не выдаётся.
Остановите процесс, снова выполните configure-telegram.py и сохраните ID.
Затем запускайте обычный `python -m publikot` или существующую службу publikot.

## 2. nginx

Добавьте location из [шаблона nginx](../deploy/oauth-nginx.conf.example)
в существующий HTTPS server для bot.itiscat.ru:

```nginx
location /telegram/webhook/ {
    access_log off;
    error_log /dev/null;
    client_max_body_size 1m;
    proxy_pass http://127.0.0.1:8081;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-Proto https;
    proxy_connect_timeout 5s;
    proxy_read_timeout 10s;
}
```

Сохраните существующий location /oauth/vk/. Не заменяйте весь конфиг домена
без проверки. Выполните `nginx -t`, затем `systemctl reload nginx` от root.
Порт 8081 слушает только localhost.

## 3. Настройки сервиса

Выберите @publikot_bot, активируйте его, выпустите API-ключ и разрешите внешний
IP сервера. Включите методы `getMe`, `sendMessage`, `answerCallbackQuery`.
Для фото также нужны `getFile`, `sendPhoto` и поддержка multipart при загрузке.

Получите URL локально на сервере:

```sh
.venv/bin/python scripts/configure-telegram.py --show-webhook-url
```

Вставьте выведенный `https://bot.itiscat.ru/telegram/webhook/<секрет>`
в поле **HTTPS адрес backend** сервиса и сохраните. Бот должен уже слушать порт.
Это секретный URL: он проверяет подлинность входящих запросов, если сервис
не предоставляет отдельную подпись. При утечке замените TELEGRAM_WEBHOOK_SECRET,
перезапустите бота и обновите адрес сервиса. nginx и приложение не журналируют URL.
Настройку setWebhook напрямую в Telegram не выполняйте — доставкой управляет сервис.

## Фото: требуется подтверждение файлового API сервиса

Стандартный `getFile` Telegram возвращает относительный file_path, для скачивания
которого Telegram требует токен BotFather. Этот проект его не запрашивает и не
обращается к Telegram напрямую. Если сервис возвращает абсолютный HTTPS file_path
на chatbot.hopop.ru, клиент скачает фото через сервис с API-ключом (до 10 МБ).
Иначе бот покажет понятную ошибку; для включения фото нужен документированный
endpoint скачивания файлов сервиса. Маршрут нельзя вывести из формата Update.
Загрузка предпросмотра использует стандартный multipart sendPhoto через сервис;
его поддержку также нужно подтвердить реальным запросом.

## Проверка после запуска

1. `/id` отвечает вашим Telegram ID; `/menu` показывает меню.
2. `/new Тест` от администратора создаёт проект; кнопки открывают настройки.
3. `/post Тестовый пост` создаёт задание; в демо-режиме показывает промпты.
4. Повтор доставки того же события не создаёт второе задание.
5. Подключите ВК через кнопку и выберите сообщество.
6. После настройки ИИ и DEMO_MODE=false проверьте исправления и публикацию
   отдельного тестового поста явным подтверждением.

Для ручных ключей публикаций Telegram используются отдельные переменные:
TELEGRAM_VK_ACCESS_TOKEN (администратор), TELEGRAM_VK_ACCESS_TOKEN_PROJECT_1,
TELEGRAM_VK_ACCESS_TOKEN_USER_123. VK_BOT_TOKEN необязателен: в Telegram он нужен
только для поиска короткого адреса VK-сообщества. Ссылки club123 и числовые ID
обрабатываются без него.

Локальные тесты проверяют webhook, меню, события, доступ и защиту от повторных
публикаций. Проверка реального сервиса, nginx, файлов и прав API требует запуска
на сервере с ключом; `--check` проверяет только getMe и username @publikot_bot.
