# Подключение сообщества кнопкой, без ключей в чате

Код проверен локально. Живая авторизация ещё не проверена: нужны собственное
приложение ВК с разрешениями API и публичный HTTPS-адрес возврата.
Сначала смотрите [результаты исследования API](vk-api-findings.md): наличие
wall/photos в SDK не гарантирует write-доступ нового VK ID-токена.
Без OAuth-настроек бот продолжает работать, /connect объясняет недостающие условия.
Старые ключи из .env.python не удаляются.

## Процесс

1. Выбрать назначенный проект, указать /vk ID_СООБЩЕСТВА.
2. Нажать «Подключить сообщество» после /select или отправить /connect.
3. Открыть одноразовую ссылку на официальный сайт ВК (10 минут).
4. Войти тем же профилем ВК, из которого пользователь пишет боту.
5. ВК возвращает код на сервер. Сервер получает ключ, проверяет личность,
   разрешения wall/photos и права редактора/администратора сообщества.
6. Ключ шифруется и сохраняется для конкретного проекта и сообщества.
   В чат отправляется только результат. Назначенные участники проекта
   смогут подтверждать публикации с этим подключением.

Смена сообщества не переносит на него старое подключение. Повторный callback,
истёкшая ссылка, отзыв доступа и смена проекта/сообщества проверяются сервером.
Подключение не публикует пост: подтверждение каждого материала остаётся обязательным.

## Сначала проверить доступ приложения к API

**Вход VK ID сам по себе не даёт права публикации.** Официальные схемы:
[wall.post](https://github.com/VKCOM/vk-api-schema/blob/master/wall/methods.json),
[фото стены](https://github.com/VKCOM/vk-api-schema/blob/master/photos/methods.json).
Для этих операций нужен пользовательский ключ с wall и photos.

До покупки домена проверьте в кабинете разработчика, доступны ли вашему приложению
эти API-разрешения и нужный flow. У обычного приложения входа могут быть доступны
только профиль, телефон и email. Обещать wall для любого нового приложения нельзя.
Если прав нет, потребуется разрешённый ВК тип приложения/согласование доступа.
Код не обходит ограничения: проверка account.getAppPermissions отвергнет ключ
без wall/photos. В режиме тестирования приложение может допускать только тестеров.

Адаптеры:

- `vkid`: Authorization Code + PKCE S256, callback с code и device_id. Официальный
  SDK: https://github.com/VKCOM/vkid-web-sdk. Только с доступными приложению scopes.
- `vk_api`: authorization code через oauth.vk.com с секретом собственного приложения.
  Только для приложений, которым ВК разрешил этот flow и wall/photos.
  Это не implicit flow и не использование ID чужого приложения.

Выбор адаптера не добавляет разрешений. Поддержку конкретного приложения нужно
проверить реальной авторизацией; локальные тесты имитируют ответ провайдера.

## HTTPS и конфигурация

Для ПублиКота зарегистрировано приложение **54825414** (Web) и адрес возврата:
`https://bot.itiscat.ru/oauth/vk/callback`. Эти публичные параметры уже используются
в коде по умолчанию и в `.env.python.example`. Права публикации приложения ещё
нужно подтвердить реальной авторизацией; регистрация приложения их не доказывает.

Для установленного бота с существующим `.env.python` после получения обновления:

```sh
cd /opt/publikot
.venv/bin/python scripts/configure-oauth.py
.venv/bin/python -m unittest discover -s tests -v
sudo systemctl restart publikot
sudo systemctl status publikot --no-pager
```

Скрипт обновляет только четыре публичные настройки OAuth, не выводит и не меняет
токены, ID администратора и остальные параметры. Повторный запуск допустим.
Запускайте его от владельца `.env.python` (в стандартной установке —
`sudo -u publikot .venv/bin/python scripts/configure-oauth.py`). Если используются
свои OAuth-приложение или домен, не запускайте этот скрипт: существующие значения
переменных окружения и `.env.python` имеют приоритет над настройками по умолчанию.
Чтобы отключить OAuth, задайте пустыми оба параметра `VK_OAUTH_CLIENT_ID` и
`OAUTH_PUBLIC_URL`. Для адаптера `vk_api` дополнительно нужен `VK_OAUTH_CLIENT_SECRET`.

Порт 8081 слушает только 127.0.0.1. Снаружи нужен HTTPS reverse proxy.
[Шаблон Nginx](../deploy/oauth-nginx.conf.example) подготовлен для `bot.itiscat.ru`.
Он предполагает сертификат в `/etc/letsencrypt/live/bot.itiscat.ru/` — проверьте
реальные пути на сервере. Наличие HTTPS само по себе не означает, что путь
`/oauth/vk/callback` уже направлен на порт 8081. Если домен уже обслуживается
существующим серверным блоком, добавьте в него только location callback из шаблона;
не создавайте второй блок с тем же server_name и не заменяйте чужие конфигурации.
Перед применением изменений Nginx выполните `sudo nginx -t`.

На callback отключены access/error logs, чтобы code/state не попадали в журналы.
В приложении access log отключён; секреты и сырые ответы провайдера не выводятся.
Страницы callback не кешируются и не передают Referer.

Перезапустите бота после настройки. Сообщение о локальном OAuth-обработчике ещё
не доказывает доступность HTTPS извне.

## Проверка реального подключения

/select НОМЕР → /vk ID → /connect → официальная авторизация → /connection.
В браузере появится результат, в боте — уведомление без ключа. После этого
проверьте тестовый пост, затем фото в тестовом сообществе. Также проверьте отказ
от авторизации и работу другого назначенного участника.

## Хранение, резервные копии, отключение

Ключи зашифрованы в vk_connections базы data/publikot-vk.sqlite3.
Файл data/oauth.key (права 600) — ключ шифрования. Для восстановления нужны
**резервная копия базы и этот файл**. Отдельно сохраняйте .env.python и фото.
Потеря oauth.key при существующих подключениях останавливает OAuth: новый ключ
не создаётся поверх старых подключений. Не отправляйте файл в Git или переписку.

/disconnect удаляет сохранённый OAuth-ключ проекта, отменяет незавершённые ссылки
и не позволяет автоматически вернуться к старому ключу из .env.python.
Повторное подключение — /connect. Разрешение у ВК при необходимости отзывается
отдельно в настройках аккаунта: удаление записи в нашей базе не отзывает его у ВК.

Автообновление истёкших ключей пока не реализовано: нужна повторная авторизация.
Пароли аккаунтов ВК бот не запрашивает.
