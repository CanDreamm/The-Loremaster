# Возврат к интерфейсу ВКонтакте

Основной интерфейс — сообщения сообщества ВК через Bots Long Poll.

Для предпросмотра изображений бот готовит отдельный JPEG с длинной стороной до
2560 пикселей через Pillow. PNG/WebP, прозрачность и расширение исходного файла
не передаются загрузчику ВК как есть; оригинал для публикации сохраняется.
Ответ загрузчика проверяется до `photos.saveMessagesPhoto`. Если ВК не принял
фото, черновик продолжает показывать текст и кнопки. Повторное открытие `/job ID`
загружает сохранённое изображение в предпросмотр без новой генерации ИИ.

После обновления, добавляющего Pillow, установите зависимости перед запуском:

```bash
cd /opt/publikot
git pull --ff-only
.venv/bin/python -m pip install -r requirements.lock
.venv/bin/python -m publikot
```

В нём доступны проекты и участники, личный Postmypost, отдельный Дзен,
концепция с манерой речи и оформлением, правила, фото персонажей, референс задания,
GenAPI, статьи и короткие истории, до трёх изображений, правки, согласование,
публикация через Postmypost с запасом две минуты и восстановление отклонённых
черновиков. Ключ ВК сообщества используется для сообщений и загрузки фото
в интерфейс; публикации на площадки используют подключения проекта.

## Переключение на существующем сервере

Сначала остановите работающий экземпляр бота (Ctrl+C при ручном запуске).
Команду переноса выполняйте при остановленном боте.

```bash
cd /opt/publikot
git pull --ff-only
.venv/bin/python -m publikot.use_vk
.venv/bin/python -m publikot --check
.venv/bin/python -m publikot
```

Уже настроенные `GENAPI_API_KEY`, модели, `DEMO_MODE`, `DATA_DIR`, OAuth и ключи
сохраняются. Команда записывает `BOT_TRANSPORT=vk` в `.env.python`.
Для ВК нужны существующий `VK_BOT_TOKEN`, `VK_BOT_GROUP_ID` и ваш `OWNER_VK_ID`.
Если они ещё не заданы, выполните `.venv/bin/python scripts/setup-python.py`;
скрипт теперь также действительно переключает транспорт на ВК. Enter сохраняет
существующие значения. ID администратора можно узнать через
`.venv/bin/python -m publikot --identify`, отправив `/id` сообществу.
Права сообщества: сообщения и фотографии, Bots Long Poll с `message_new`
и `message_event`, включённые возможности ботов. См. [настройку ВК](vk-setup.md).

## Перенос проектов

`use_vk` читает `DATA_DIR/publikot-telegram.sqlite3`, а если его нет — прежнюю
`DATA_DIR/publikot.sqlite3`. Записывает в отдельную `publikot-vk.sqlite3`.
Источник открывается только для чтения. Перед открытием существующей базы ВК
создаётся её SQLite backup в `DATA_DIR/backups` (с правами 0600).

Переносятся проекты, принадлежащие `OWNER_TELEGRAM_ID`, под владельца `OWNER_VK_ID`:
настройки промптов и изображений, материалы, собственные личные токены Postmypost
и сеансы Дзена, подключения площадок. Нужен общий исходный `platforms.key` в
том же DATA_DIR. Фото остаются по своим существующим путям на сервере; папку
`data` и ключи не удаляйте.

Существующие проекты ВК не перезаписываются. При совпадении названия импортированное
получает суффикс Telegram. Повторный запуск не создаёт дубли ранее импортированных
проектов. При повторном импорте уже перенесённые настройки не синхронизируются заново.

Если у администратора ВК уже другой токен для этого сервиса, он сохраняется;
конфликтующее подключение проекта нужно заново выбрать через «Площадки».
Подключения других пользователей не присваиваются администратору. В отчёте
`connections_to_reconnect` показывает число таких площадок. Назначения, разрешения
и ID пользователей Telegram не копируются: назначьте участников по их ID ВК.
Проекты, принадлежащие другим пользователям Telegram, автоматическая команда
не переносит. Для них требуется отдельное явное соответствие владельцев.

История заданий, очереди публикаций, согласования, кнопки и OAuth-сессии Telegram
не копируются. Старые отправки никогда не запускаются повторно. Они остаются в
исходной базе; уже принятые Postmypost записи продолжают обрабатываться сервисом.

Только переключить интерфейс без импорта:

```bash
.venv/bin/python -m publikot.use_vk --no-import
```

## Проверка после переключения

1. Напишите `/menu` сообществу ВК и откройте «Мои проекты».
2. Проверьте концепцию, настройки, фото персонажей и площадки проекта.
3. Назначьте участников по ID ВК; их `/id` отвечает в сообщениях сообщества.
4. Прикрепите фото к заданию. ВК скачивает фото со своих CDN, без Telegram-сервиса.
5. Проверьте текст, создайте изображения, при необходимости исправьте одну картинку.
6. Подтвердите публикацию и проверьте `/status`. Postmypost может оставаться в очереди
   до запланированного времени, поэтому принятие запроса не равно публикации.

Локальные HTTP-тесты проверяют именно транспорт ВК: приём событий с фото,
скачивание референсов, передачу байтов GenAPI, загрузку готовых картинок в сообщения
ВК и callback-кнопки. Отдельный сквозной тест проверяет участников, полный текст,
три картинки, Postmypost и Дзен с проверкой контракта официального SDK Postmypost.
Для подтверждения работы реальных аккаунтов нужен запуск с ключами на вашем сервере.
