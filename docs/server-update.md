# Обновление существующего сервера

Команды ниже выполняются по SSH от `root` для проекта в `/opt/publikot`.
Если вошли другим пользователем, сначала выполните `sudo -i`.
Копируйте только команды, без приглашения `root@server:…#`.
Выполняйте блоки по очереди. При ошибке остановитесь и не переходите к следующему.

## Сначала определите способ запуска

```sh
cd /opt/publikot
git status --short --branch
getent passwd publikot
systemctl show publikot.service -p LoadState -p User -p WorkingDirectory -p ExecStart
ps -eo user,pid,args | grep -E '[p]ython.*publikot|[p]ython.*bot'
```

`getent` без вывода означает, что пользователя нет. Если последняя команда
ничего не нашла, подходящего процесса не видно. Эти результаты сами по себе
не означают, что установка сломана.

| Что обнаружено | Что использовать |
| --- | --- |
| Проект есть, пользователя `publikot` нет, `LoadState=not-found` | Вариант А: обновление от root без службы. |
| Есть пользователь `publikot`, загруженная служба имеет `User=publikot` и каталог `/opt/publikot` | Вариант Б: обновление установки со службой. |
| Служба запускает другого пользователя или другой каталог | Сначала уточните текущую схему; команды для `publikot` автоматически не подходят. |
| Каталога проекта нет | Нужна [первая установка](python-deploy.md#первая-установка). |

**Наличие `/opt/publikot` не означает, что пользователь и служба уже созданы.**
Если бот запускается вручную, остановите его через Ctrl+C в его терминале.
Если он работает через другую службу, Docker, tmux или screen, сначала найдите
и остановите именно этот экземпляр. Одновременно запускается один бот.

Примеры ниже используют `.env.python` и стандартный `DATA_DIR=./data`.
Если в вашей конфигурации указан другой каталог данных, копируйте его фактический
путь. Содержимое `.env.python` не отправляйте в чат и не добавляйте в Git.

## Вариант А: root, без пользователя publikot и без службы

В этом варианте **не нужны** `sudo -u publikot` и `systemctl stop publikot`.
Сначала остановите ручной процесс бота, если он работает.

### 1. Резервная копия

```sh
cd /opt/publikot
umask 077
mkdir -p backups
chmod 700 backups
tar -czf backups/before-update-$(date +%Y%m%d-%H%M%S).tar.gz .env.python data
```

Архив содержит настройки, базу с WAL-файлами, фото и `data/oauth.key`, если он
есть. Архивировать `data` таким способом нужно при остановленном боте.
Если `.env.python` или `data` не найдены, сначала определите фактические пути;
не продолжайте после ошибки архивации. Архив содержит секреты: храните его вне
Git и сделайте защищённую копию вне VPS.

### 2. Обновление и проверки

```sh
git pull --ff-only origin master
.venv/bin/python -m pip install -r requirements.lock
.venv/bin/python -m unittest discover -s tests -q
.venv/bin/python -m pip check
```

Ожидаются `OK` в тестах и отсутствие конфликтов зависимостей. Количество тестов
меняется с обновлениями. При любой ошибке остановитесь. Эти проверки не проверяют
ключи ВК, баланс Yandex и публичную доступность callback.

### 3. Настройки текущего приложения ВК, если требуется

```sh
.venv/bin/python scripts/configure-oauth.py
```

Скрипт задаёт приложение `54825414` и домен `https://bot.itiscat.ru`, сохраняя
секреты и выбранного провайдера. Он не создаёт службу, не устанавливает nginx
и не подтверждает права приложения. Для подготовки текста OAuth не обязателен.

### 4. Маршрут выбора сообществ

Для нового сценария «Добавить сообщество» выполните
[обновление nginx](#nginx-для-выбора-сообществ) ниже до запуска бота.

### 5. Пробный запуск

```sh
.venv/bin/python -m publikot
```

Оставьте терминал открытым и отправьте `/start` боту в ВК. Этот запуск не
обеспечивает постоянную работу после закрытия SSH. После проверки остановите
его через Ctrl+C и настройте службу по разделу ниже.

## Вариант Б: пользователь и служба publikot уже существуют

### 1. Остановка и резервная копия

```sh
systemctl stop publikot
cd /opt/publikot
umask 077
mkdir -p backups
chmod 700 backups
tar -czf backups/before-update-$(date +%Y%m%d-%H%M%S).tar.gz .env.python data
```

Архив создаётся от root с доступом только для root. Убедитесь также, что не
работает отдельный ручной процесс бота. При ошибке копирования не продолжайте.

### 2. Обновление и проверки

```sh
sudo -u publikot git pull --ff-only origin master
sudo -u publikot .venv/bin/python -m pip install -r requirements.lock
sudo -u publikot .venv/bin/python -m unittest discover -s tests -q
sudo -u publikot .venv/bin/python -m pip check
```

При необходимости примените настройки текущего приложения:

```sh
sudo -u publikot .venv/bin/python scripts/configure-oauth.py
```

### 3. Запуск после успешных проверок

Для нового сценария «Добавить сообщество» сначала выполните
[обновление nginx](#nginx-для-выбора-сообществ) ниже.

```sh
systemctl start publikot
systemctl status publikot --no-pager
journalctl -u publikot -n 50 --no-pager
```

Проверьте `/start` в ВК. Для обновления Python-кода переустанавливать службу
не нужно. Если меняли unit-файл, сначала сравните его с установленным, сохраните
свои настройки и выполните `systemctl daemon-reload` перед запуском.

## nginx для выбора сообществ

После обновления кода в действующем HTTPS-конфиге `bot.itiscat.ru` маршрут
должен пропускать callback и страницу подтверждения выбора. Обновление файла
`deploy/oauth-nginx.conf.example` через Git не изменяет действующий nginx-конфиг.

Найти файл и существующие маршруты можно командой:

```sh
nginx -T 2>/dev/null | grep -n -E '^# configuration file|server_name|location.*oauth/vk'
```

В файле сервера `bot.itiscat.ru` сохраните резервную копию конфигурации и замените
только строку открытия блока:

```nginx
location = /oauth/vk/callback {
```

на:

```nginx
location /oauth/vk/ {
```

Содержимое блока, настройки сертификатов и другие virtualhost сохраняются.
Если префиксный маршрут уже настроен, повторное изменение не нужно.
Затем:

```sh
nginx -t && systemctl reload nginx
```

Если проверка nginx завершилась ошибкой, исправьте конфиг до запуска бота.
При включённом `vk_implicit` после запуска этот адрес должен вернуть HTTP 200
и заголовок `X-Publikot-OAuth: 1`:

```sh
curl -sS -D - -o /dev/null https://bot.itiscat.ru/oauth/vk/callback
```

В code flow пустой callback возвращает HTTP 400 с тем же заголовком.
После этого откройте в боте «Добавить сообщество» → «Выбрать сообщества ВК».
Авторизуйтесь своим аккаунтом, отметьте сообщества, подтвердите выбор и вернитесь
в «Мои сообщества». ID, названия и ключи в чат вводить не нужно.
Этот шаг не меняет выбранный OAuth-провайдер и не добавляет прав приложению ВК.

## Создание службы после установки от root

Выполните после успешного ручного запуска. Перед этим остановите ручной процесс
через Ctrl+C. Если служба уже есть, не заменяйте её вслепую: используйте вариант Б.

Проверьте пользователя:

```sh
getent passwd publikot
```

Только если вывода нет, создайте его:

```sh
adduser --system --group --home /opt/publikot --no-create-home publikot
```

Подготовьте права. Это переводит существующую установку в `/opt/publikot`
на пользователя `publikot`, сохраняя настройки и данные:

```sh
cd /opt/publikot
mkdir -p data
chown -R publikot:publikot /opt/publikot
chmod 700 data
chmod 600 .env.python
if [ -f data/oauth.key ]; then chmod 600 data/oauth.key; fi
sudo -u publikot .venv/bin/python -m unittest discover -s tests -q
```

При нестандартном `DATA_DIR` настройте его владельца и `ReadWritePaths` в unit-файле.
После успешных тестов установите службу:

```sh
cp deploy/publikot.service /etc/systemd/system/publikot.service
systemctl daemon-reload
systemctl enable --now publikot
systemctl status publikot --no-pager
```

Ожидается `active (running)`. Бот продолжит работать после закрытия SSH
и будет запускаться после перезагрузки VPS. После изменения `.env.python`
перезапускайте службу командой `systemctl restart publikot`.

## Частые ситуации

| Сообщение или ситуация | Что делать |
| --- | --- |
| `Unit publikot.service not loaded` / `not found` | Служба не создана или называется иначе. Начните с диагностики; повторять stop/restart отсутствующей службы не нужно. |
| `sudo: unknown user publikot` | Пользователь не создан. Используйте вариант А или создайте службу по инструкции выше. |
| `sudoers_audit` после `unknown user` | Сначала устраните отсутствие пользователя. На основании этого вывода не меняйте настройки sudo. |
| Git сообщает о локальных изменениях или невозможности fast-forward | Остановитесь и сохраните свои изменения. Не используйте `reset --hard`, force и удаление каталога проекта. |
| `detected dubious ownership` | Проверьте владельца проекта и выполняйте Git от пользователя установки. Не отключайте проверку через `safe.directory=*`. |
| В `git status` виден `.env.python.swp` | Это временный файл редактора; он может содержать секреты. Не добавляйте его в Git и не показывайте содержимое. Сначала проверьте, закончено ли редактирование `.env.python`. |
| `.venv/bin/python` не найден | Проверьте каталог проекта. Если окружение ещё не создавалось, используйте первую установку. Существующее окружение без причины не удаляйте. |
| Служба не запускается | Проверьте status и journalctl из варианта Б. Перед передачей вывода убедитесь, что он не содержит секретов. |
| Бот выдаёт демо-текст | Проверьте `YANDEX_API_KEY`, `YANDEX_FOLDER_ID` и `DEMO_MODE=false`, затем перезапустите текущий процесс или службу. |
| Бот работает, а авторизация нет | Проверьте провайдер, HTTPS, reverse proxy и Redirect URL по [oauth.md](oauth.md). Обновление кода не настраивает их автоматически. |
| При запуске порт `127.0.0.1:8081` занят | Выполните `ss -ltnp 'sport = :8081'` и `ps -eo pid,ppid,args`, определите работающий экземпляр и остановите именно его. Новое сообщение «Публикот запущен» выводится только после запуска OAuth-обработчика. |

Не копируйте `.env.python.example` поверх настроенного `.env.python`, не удаляйте
`data` и не заменяйте утраченный `oauth.key` новым при существующих подключениях.
Для восстановления нужны база и прежний ключ шифрования.

Для копии базы во время работы используйте `scripts/backup.py`, как описано
в [README](../README.md#проверки-и-резервная-копия); фото, настройки и ключ
сохраняйте отдельно. Один файл работающей SQLite-базы не является полной копией
из-за WAL. Для обновления проще остановить бот и создать полный архив выше.

После установки проверьте [минимальный сценарий](minimal-start.md): добавление
сообщества, выбор, текст и исправление. Публикацию проверяйте отдельно в тестовом
сообществе после подтверждения текста.
