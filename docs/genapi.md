# GenAPI: текст, иллюстрации и публикация

Основной бот использует GenAPI вместо YandexGPT. Интерфейсы ВК и Telegram
используют один и тот же сценарий; их базы и идентификаторы пользователей разделены.

## Включение на Ubuntu

Пока ключа нет, оставьте `DEMO_MODE=true`. Бот позволяет настраивать проекты,
участников, площадки и смотреть сформированные промпты; платных запросов и
публикации демо-текстов нет. Демо не имитирует реальные изображения.

Когда будете готовы, добавьте в `/opt/publikot/.env.python`:

```dotenv
GENAPI_API_KEY=ваш_ключ_из_кабинета_GenAPI
GENAPI_TEXT_MODEL=gpt-6-luna
GENAPI_IMAGE_MODEL=seedream-v5-lite
DEMO_MODE=false
```

Ключ хранится только на сервере, не в Git и не в сообщениях бота. Старые переменные
`YANDEX_API_KEY` / `YANDEX_FOLDER_ID` основным ботом больше не используются.
Существующие настройки транспорта, Postmypost и сеанса Дзена сохраняются.
Новые зависимости не требуются; SQLite мигрирует автоматически при запуске.
Перед обновлением остановите прежний процесс и сохраните резервную копию `data`.
Запускайте только один экземпляр бота с одной базой.

Обновление:

```bash
cd /opt/publikot
git pull --ff-only
.venv/bin/python -m publikot
```

## Сценарий

1. Администратор создаёт проект в «Мои проекты» и назначает участников.
2. Владелец подключает свои площадки в «Площадках»: личный Postmypost и/или
   отдельный сеанс канала Дзена. Участникам не передаются его секреты.
3. В настройках проекта задайте концепцию (включая манеру речи и оформление),
   правила текста, фото персонажей, шаблоны промптов. В «Генерации изображений» выберите
   количество **0–3**, квадратный/горизонтальный/вертикальный формат и правила картинки.
   По умолчанию — одно квадратное изображение.
4. Участник отправляет тему. Для статьи прямо укажите её формат и объём в задании
   или правилах проекта. Если ничего не указано, промпт просит короткий пост до
   500 символов. Верхняя граница результата — 30000 символов и 10000 токенов
   ответа с учётом рассуждений модели. Конкретный объём — инструкция модели,
   а не гарантия точного числа символов; обрезанный по токенам ответ не принимается.
5. Бот передаёт GenAPI полный текстовый контекст и реальные изображения-референсы
   в Base64, с указанием их ролей. Фото из задания служит референсом и само по себе
   не попадает в публикацию.
6. После проверки текста нажмите «Создать / проверить изображения». Каждый
   запрос создаёт одну иллюстрацию отдельной сцены по согласованному тексту и
   общим референсам. Результаты скачиваются на сервер, поскольку ссылки GenAPI
   временные. Во время генерации задание заблокировано от изменений и отправки.
7. Для правки нажмите «Изменить изображение N». Оплачивается новая генерация
   только выбранной картинки; прежний вариант также передаётся как референс.
   Текст и остальные изображения сохраняются. Ручная замена фото заменяет первую
   картинку, сохраняя остальные.
8. «Опубликовать» появляется после подготовки нужного числа картинок. Отдельное
   подтверждение отправляет весь согласованный текст и все изображения на
   подключённые площадки. Изменение настроек количества/формата относится к
   новым заданиям, текущее использует сохранённый снимок настроек.
9. Postmypost принимает публикацию в очередь: окончательное состояние смотрите
   через `/status` или повторное открытие задания. «Принято в очередь» не означает
   «опубликовано». Дзен использует экспериментальный editor API: требуется
   действующий сеанс, а изменения API могут потребовать обновления адаптера.

## Стоимость и отказоустойчивость

Отдельных настроек «Тон общения» и «Визуальный стиль» больше нет. При первом
запуске обновления их прежние текстовые значения и подпись к фото стиля один раз
добавляются в концепцию без повторения уже имеющегося текста. Отдельное фото
стиля исключается из новых запросов; его файл остаётся в архивных данных.
Фото персонажей и референс к заданию продолжают использоваться. Старые сохранённые
версии и результаты платных запросов не переписываются.

Объём текста определяется последними замечаниями, затем заданием, затем правилами
и шаблоном проекта. При заданном объёме или запросе статьи бот не добавляет своё
числовое правило «до 500 символов». Оно применяется только при отсутствии
требований к объёму. Указание конкретного количества символов трактуется как
целевой объём; «до» и «не более» — как верхняя граница. В предпросмотре виден
фактический объём с пробелами. Это инструкции модели, а не гарантия точного числа
символов: текст не дополняется механически, автоматических платных переписываний
для подгонки длины нет. Для уже созданного короткого варианта используйте
«Изменить текст» с нужным объёмом — это отдельная генерация текста.

- Текст — `gpt-6-luna`, `reasoning_effort=low`, без автоматического перехода на
  более дорогую модель. Модель текста можно изменить через `GENAPI_TEXT_MODEL`.
- Изображения — `seedream-v5-lite` или `nano-banana-lite`, выбор через
  `GENAPI_IMAGE_MODEL`. Для них используются разные параметры формата.
- Длинный контекст иллюстрации (больше 2400 символов) сначала передаётся текстовой
  модели вместе со всеми настройками, статьёй, замечаниями и референсами.
  Она составляет отдельное короткое описание сцены на английском с сохранением
  визуальных требований. Статья не обрезается и не меняется. Описание больше
  2400 символов или пустое останавливает отправку картинки. Это внутренний бюджет
  нашего приложения, а не утверждение о максимуме GenAPI. Такая подготовка —
  дополнительный платный текстовый запрос на каждую сцену; его ID, результат и
  стоимость сохраняются отдельно как `image_prompt` и используются повторно
  при проверке результата. Если картинка уже принята GenAPI, новая подготовка
  не запускается даже после обновления бота.
- Референсы для моделей изображений передаются прямой загрузкой
  `multipart/form-data` в файловых частях `image_urls[]`, с правильными MIME-типом
  и расширением. Текстовые модели продолжают получать референсы как Base64 URI
  внутри JSON messages. На CDN или сторонний хостинг исходные фото не загружаются.
- Один ключ GenAPI обслуживает весь бот: расходы всех допущенных участников
  списываются с одного баланса. Отдельные пользовательские ключи GenAPI здесь
  не реализованы. Postmypost по-прежнему подключается личным токеном пользователя.
- Текстовые правки не запускают картинки заново. Изменённый текст может требовать
  отдельной правки иллюстрации — это решает пользователь перед публикацией.
- Перед платным POST сохраняется намерение отправки; после ответа сохраняется ID.
  При тайм-ауте POST, ошибке или перезапуске автоматического платного повтора нет.
- Если ID известен, `/resume` проверяет прерванный текстовый запрос; для картинок
  повторно нажмите «Создать / проверить изображения». Уже готовые результаты
  используются повторно. Сохранённые ID и результаты видны в таблице `ai_requests`.
  Поле `cost` сохраняет значение, сообщённое API, без собственной конвертации единиц.
- Если ID потерян при отправке, проверьте историю GenAPI в кабинете. Бот не может
  безопасно определить, был ли оплачен и выполнен запрос. Для изображений кнопка
  «Создать / проверить изображения» предложит отдельно подтвердить новую попытку
  с предупреждением о возможной оплате. Текст и известные ID/результаты сохраняются,
  запись с потерянным ID остаётся в предыдущей версии. Старый бот не сохранял
  различие между HTTP 422 и потерей ответа, поэтому такие записи автоматически
  разблокировать нельзя. Для новой попытки текста создайте новое задание.
  Запрос с явным конечным статусом `error` также не повторяется.
- Документированный HTTP 422 с `errors_validation` сохраняется как `rejected`.
  Бот показывает модель, отклонённые поля и распознанные ограничения, например
  минимум/максимум. После исправления параметров следующее действие пользователя
  может отправить запрос повторно; автоматического повтора нет. Пустые необязательные
  `image_urls` не передаются. Размеры/лимиты модели по одному коду HTTP не угадываются.
  Распознанные сообщения валидации также показываются с удалением ключа, URL,
  длинных закодированных данных и значений в кавычках: подробная причина больше
  не заменяется одним словом «отклонено».
- Ошибка картинки сохраняет текст на согласовании. Прерванная генерация изображений
  после перезапуска возвращает задание на согласование, сохранив внешние ID.
- Файлы — JPEG/PNG/WebP, до 10 МБ на файл. Секрет GenAPI не передаётся CDN.
  Перенаправления при скачивании отключены. Файлы результата сохраняются в `data/generated`.
- HTTP ошибки показываются без сырого тела ответа, токенов и подписанных URL.
  Полные пользовательские тексты и Base64 не копируются из ошибок в сообщения.
- Ни генерация, ни публикация с неизвестным результатом не повторяются автоматически.

## Диагностика существующего запроса на сервере

Если бот сообщил об отсутствии текста, после обновления сначала откройте нужное
задание и отправьте `/resume`. Исправленный разбор поддерживает вложенные
`choices → message → content`, текстовые блоки и поле `full_response`. Старый
сохранённый пустой результат перечитывается GET-запросом по тому же ID. Новая
платная генерация не создаётся. Размышления, входные сообщения и альтернативные
варианты ответа не добавляются в публикацию.

Для проверки, что сформировано на отправку и что реально возвращается по ID:

```bash
cd /opt/publikot
.venv/bin/python -m publikot.genapi_check
# Либо конкретное задание:
.venv/bin/python -m publikot.genapi_check --job 123
# Последний запрос изображений (или добавьте --job 123 --slot 0):
.venv/bin/python -m publikot.genapi_check --kind image
# Подготовленное описание сцены — отдельный сохранённый текстовый запрос:
.venv/bin/python -m publikot.genapi_check --kind image_prompt
```

Команда открывает базу только для чтения, не меняет статусы и выполняет только
не более одного GET к GenAPI. Для отклонённого запроса без ID сеть не используется.
Поэтому её можно запускать рядом с работающим ботом.
Показывает номер задания/ID запроса, модель, длину и хеш восстановленного промпта,
наличие настроек, роли референсов и совпадение их Base64 с исходными файлами,
статус ответа и количество извлечённых символов. Тело промпта, ответ, ключи,
Base64 и ссылки не выводятся. Сводка исходящего запроса восстанавливается из
сохранённого контекста и текущего построителя; это не перехват сетевого трафика.
Структура реального ответа позволяет диагностировать новый формат без раскрытия
содержимого. Вывод можно передать для разбора ошибки.

Для новых запросов поле `submitted` берётся из `ai_requests.request_meta`, сохранённого
перед отправкой: модель, имена полей, размеры, количество/длины референсов и длина
промпта. Это описание фактически сформированного запроса без его содержимого.
Для `rejected` выводится безопасная сохранённая причина отказа. Старые HTTP 422
восстановить из базы невозможно: прежний код отбрасывал тело ответа.

## Что проверено без ключей

Автотесты используют локальные HTTP-сервисы. Сквозной сценарий для ВК и Telegram:
создание проекта → назначение участника → настройки и референсы → статья →
три картинки → правка одной → подтверждение → загрузка трёх файлов в Postmypost
и Дзен → проверка состояния → отклонение повторного подтверждения.
Проверяются тайм-ауты, сохранение ID, отсутствие повторного платного POST,
перезапуск, сохранение версий, права доступа, отсутствие секретов в ошибках.

Это подтверждает работу кода с заявленным протоколом API, но не доступность моделей,
реальные цены/списания, качество русского текста, сходство персонажей, тариф/права
Postmypost и совместимость текущего editor API Дзена с реальным аккаунтом.
Для окончательной проверки после добавления ключа создайте один тестовый проект
с тестовыми площадками и пройдите тот же сценарий вручную. Прежде чем массово
публиковать, сравните несколько собственных заданий на двух моделях изображений.
