# Публикация через браузер: ВК и Дзен

Бот управляет Chromium через Playwright: открывает редактор, вставляет текст,
прикрепляет готовое фото и нажимает кнопки сайта. Ключи API публикаций,
приложение ВК, OAuth callback и публичный HTTPS для этого режима не нужны.
API ВК остаётся транспортом сообщений бота. Генерация текста также остаётся
независимой: DEMO_MODE=true запрещает публикацию демонстрационных текстов.

## Установка

Из каталога проекта, тем же пользователем ОС, который запускает бота:

```sh
.venv/bin/python -m pip install -r requirements-browser.lock
.venv/bin/python -m playwright install chromium
```

На Linux при отсутствии системных библиотек администратор устанавливает их:

```sh
.venv/bin/python -m playwright install-deps chromium
```

Первый вход требует графического рабочего стола на компьютере с ботом.
На сервере используйте его графический сеанс через VNC/RDP либо X forwarding.
Один Xvfb без доступа к окну не позволяет выполнить ручной вход. Установку
Chromium и вход выполняйте от пользователя службы, с тем же DATA_DIR, что у бота.
Не запускайте Chromium от root с отключённой песочницей.

## Выбор проекта и площадки

В боте: «Мои сообщества» → «Добавить проект без API» → название → ВК или Дзен.
Существующий проект: «Настройки проекта» → «Площадка публикации».
Указать площадку может владелец проекта. Участники с доступом к проекту могут
согласовывать и публиковать задания через сохранённый профиль его владельца.

Для ВК отправьте полную ссылку, например `https://vk.ru/club123`.
Для Дзена нужна ссылка **на редактор вашего канала**:
`https://dzen.ru/profile/editor/id/ID_КАНАЛА`, а не публичная ссылка на канал.
ID возьмите из адресной строки открытой Студии Дзена.

Вместо меню можно отправить в выбранном проекте:

```text
/browser vk https://vk.ru/club123
/browser dzen https://dzen.ru/profile/editor/id/ID_КАНАЛА
```

Один проект имеет одну площадку. Для публикации в обе создайте два проекта.
Старые проекты сохраняют прежний API-режим до явного выбора браузера.
После смены площадки создайте новое задание: старое привязано к прежнему адресу.

## Вход

Узнайте номер проекта из списка в боте. Например, для проекта №1:

```sh
.venv/bin/python -m publikot.browser_login --project 1 --platform vk --target https://vk.ru/club123
```

Для отдельного проекта №2 в Дзене:

```sh
.venv/bin/python -m publikot.browser_login --project 2 --platform dzen --target https://dzen.ru/profile/editor/id/ID_КАНАЛА
```

В открывшемся окне войдите в аккаунт, самостоятельно пройдите 2FA/капчу,
откройте нужное сообщество/канал и проверьте право публикации. Затем нажмите
Enter в терминале: окно закроется, профиль сохранится. Утилита входа ничего
не публикует. Пароли и cookie не отправляются в чат. При истечении входа
повторите команду. `/connection` показывает наличие сохранённого профиля;
это не проверка актуальности входа и прав.

Профили находятся в `DATA_DIR/browser/НОМЕР_ПРОЕКТА/vk` или `dzen`.
Содержимое даёт доступ к аккаунту: храните каталог приватно, вне Git.
Не открывайте один профиль одновременно в боте и утилите входа.
Профиль блокируется между процессами. Удаление проекта в боте удаляет его
записи в базе; профиль браузера удаляется вручную на сервере после закрытия
браузера. Номера проектов не переиспользуются.

## Публикация

Создайте новое задание, проверьте текст и фото, нажмите «Опубликовать».
Публикуется только версия, которую вы подтвердили. Фото-референс задания
не отправляется автоматически: готовую иллюстрацию добавьте в предпросмотре.

ВК: текст и необязательное фото на стене выбранного сообщества.
Дзен: **статья**, отдельный заголовок первой строкой до 140 символов,
пустая строка и основной текст. Заголовок и тело заполняются в разных полях.
При отсутствии заголовка или превышении его длины отправка останавливается;
начало статьи не используется как сокращённый заголовок.


После отправки бот ищет ссылку на новую публикацию с текстом задания.
Успешный клик сам по себе не означает успех. Если ссылка не подтверждена или
возник тайм-аут после финального нажатия, задание получает статус «проверьте
площадку» и **не отправляется повторно**, включая перезапуск бота.
Проверьте стену/Студию вручную перед созданием нового задания.

Вход, отсутствие прав, капча или изменение редактора могут остановить сценарий.
Капча не обходится: повторите ручной вход. Сценарий работает последовательно
в обработчике бота; фонового планировщика нет.

## Изменения интерфейсов сайтов

Реальные отправки пока не проверены с аккаунтами владельца. Автоматические
тесты проверяют маршрутизацию без API, защиту от повторов, блокировку профиля,
заполнение редактора и обработку неопределённого результата с имитацией браузера.
Структура живого редактора может отличаться от исходных CSS-селекторов.

Для диагностики в графическом сеансе задайте `BROWSER_HEADLESS=false`
в `.env.python`, перезапустите бота и проверьте редактор. Не запускайте повторную
публикацию, пока не выяснили результат предыдущей.

Селекторы по умолчанию перечислены в `publikot/browser_publish.py`.
Переопределить отдельные можно в `DATA_DIR/browser-selectors.json`:

```json
{
  "vk": {"body": "#post_field", "publish": "#send_post"},
  "dzen": {"publish": "button:has-text(\"Опубликовать сейчас\")"}
}
```

Используйте селекторы, которые однозначно выбирают один элемент. В Дзене `next`
открывает настройки публикации, `publish` выполняет окончательную отправку.
Не назначайте кнопкам промежуточных шагов финальное действие. Для фото `file`
выбирает поле загрузки, `image_ready` — уже загруженное изображение в редакторе.
Несовпадение селекторов приводит к остановке, а не к отправке вслепую.
