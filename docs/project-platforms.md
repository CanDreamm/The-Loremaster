# Проекты, пользователи и площадки публикации

Интерфейс выбирается через BOT_TRANSPORT: личные сообщения ВК или Telegram
через сервис Chatbot. Генерация, промпты,
референсы, версии текста и согласование работают как раньше. Перенос интерфейса
бота в Telegram сохранён из актуального master; публикации работают в обоих транспортах.

## Модель

- «Мои проекты» — список назначенных пользователю проектов.
- Каждый проект имеет общие настройки, задания, участников и несколько площадок.
- Каждый пользователь сохраняет собственный токен Postmypost. Токен не копируется
  в проекты и не показывается другим участникам.
- Пользователь подключает доступные его токену аккаунты к выбранному проекту.
  На одной странице «Площадки» могут быть подключения разных пользователей.
- Участники проекта могут согласовывать публикацию во все его площадки, используя
  сохранённые подключения. Собственный токен для такой работы им не требуется.
- Для отправки используется токен подключившего конкретную площадку пользователя,
  а не токен текущего согласующего, владельца бота или другого проекта.
- При отзыве доступа к боту или членства подключившего пользователя новые отправки
  через его подключение блокируются.
- Одинаковое сообщество с тем же channel/external_id нельзя добавить к одному
  проекту повторно через другой токен: это защищает от двойной отправки.

## Личный Postmypost

1. В кабинете Postmypost подключите нужные социальные аккаунты к проектам.
2. Создайте персональный access token с доступом к API по документации сервиса.
3. В боте откройте «Мой Postmypost» → «Добавить токен» и отправьте токен в личный
   диалог бота. После успешной проверки удалите исходное сообщение с токеном.
   Бот не повторяет и не показывает токен, но исходное сообщение в выбранном мессенджере остаётся,
   пока вы его не удалите.
4. Альтернатива без передачи секрета в сообщения: остановите службу бота и
   выполните от её пользователя ОС из каталога проекта:

```sh
.venv/bin/python -m publikot.platform_setup --user 123456
```

`123456` — ID пользователя выбранного транспорта (Telegram или ВК), которому
принадлежит токен, а не ID проекта. Команда использует BOT_TRANSPORT из .env.python.
Токен вводится скрыто через getpass. Пользователь должен быть допущен к боту.
После настройки запустите службу.

В обоих вариантах токен проверяется запросом списка проектов Postmypost, затем
шифруется Fernet. Старое подключение при неуспешной проверке нового не заменяется.

## Создание и подключение площадок

«Мои проекты» → «Добавить проект» → название → «Площадки» →
«Добавить из Postmypost» → проект в вашем Postmypost → нужный аккаунт.
Повторите для остальных аккаунтов. Списки используют пагинацию; выбор привязан
к пользователю, локальному проекту и текущей версии токена и действует 10 минут.
Перед подключением и отправкой бот заново проверяет доступность аккаунта.

«Мой Postmypost» заменяет или отключает только ваш токен. Отключение действует
на все использующие его площадки. Уже созданные в Postmypost публикации при этом
не отменяются. Владелец проекта, администратор бота или подключивший площадку
пользователь может отключить её через «Площадки» → выбранный аккаунт.

Токен, доступ к тарифу API и реальные разрешения площадок необходимо проверить
в вашем кабинете. Наличие валидного токена само по себе не гарантирует права
на публикацию и доступ ко всем эндпоинтам.

## Участники

Администратор, как раньше, допускает пользователей по ID выбранного мессенджера через «Управление
доступом» или `/allow ID`. Затем владелец проекта или администратор открывает
проект → «Участники» → «Добавить участника» и вводит ID. Там же можно исключить
участника. Существующие `/assign ПРОЕКТ ID`, `/unassign ПРОЕКТ ID`, общие задания
и ограничения видимости проектов сохранены. Глобальный доступ назначает только
администратор; владелец проекта назначает уже допущенных пользователей.

Базы Telegram и ВК отдельные; ID, назначения и токены не переносятся автоматически
между транспортами.

Назначение в проект означает разрешение готовить, редактировать и подтверждать
посты для его площадок. Токены других участников при этом не раскрываются.

## Дзен: прямой неофициальный editor API

Дзен использует отдельный адаптер `publikot/dzen_api.py`, без Postmypost,
Telegram-кросспостинга и браузерной автоматизации. Реализованы HTTP-запросы
создания статьи, загрузки одной фотографии, сохранения и финальной публикации.
Протокол сверён с открытым примером:
https://github.com/nws98123-prog/dzen-autopublisher/blob/main/dzen_direct_api.py

Это экспериментальная интеграция без стабильного публичного контракта. Реальные
запросы с вашим сеансом ещё не проверены. Смена editor API, истечение cookie,
CSRF, дополнительные проверки входа или fingerprint могут остановить отправку.
Обход капчи/защит и автоматическое получение нового сеанса не реализованы.

Для каждого канала импортируется авторизованный сеанс пользователя отдельно.
На своём компьютере войдите в собственную Дзен-студию. Из инструментов
разработчика браузера возьмите cookie домена dzen.ru и X-Csrf-Token запроса
редактора. Не публикуйте HAR и не отправляйте cookie в чат: они предоставляют
доступ к аккаунту. При необходимости используйте реальные X-FP-Token/User-Agent
своего сеанса; адаптер не генерирует их.

Подготовьте на сервере приватный JSON с правами 600, например
`data/dzen-session.json`:

```json
{
  "publisher_id": "ID_КАНАЛА",
  "cookies": {"ИМЯ_COOKIE": "ЗНАЧЕНИЕ_COOKIE"},
  "csrf_token": "ЗНАЧЕНИЕ_X_CSRF_TOKEN"
}
```

Необязательные поля — `fp_token`, `user_agent`. Используется только заданный
домен dzen.ru; перенаправления не выполняются. Файл должен содержать рабочие
данные именно вашего сеанса. Примерные строки не являются действительными.

Остановите бота и импортируйте от его пользователя ОС:

```sh
chmod 600 data/dzen-session.json
.venv/bin/python -m publikot.platform_setup --user 123456 --dzen-file data/dzen-session.json
```

Затем запустите бота. В проекте выберите «Площадки» → «Подключить Дзен» →
свой канал. Пользователь может импортировать несколько каналов; сеансы хранятся
по ключу `dzen:publisher_id`. Заменить/отключить сеанс можно отдельно для канала:

```sh
.venv/bin/python -m publikot.platform_setup --user 123456 --disconnect dzen:ID_КАНАЛА
```

Эти команды тоже выполняются при остановленном боте. После успешного импорта
исходный JSON больше не требуется адаптеру; храните его приватно или удалите.

Формат — статья. Первые 140 символов первой строки становятся заголовком;
полный согласованный текст сохраняется в содержимом без интерпретации HTML.
Фото добавляется в содержимое и обложку. Если фото не загрузилось, статья без
него не публикуется. Успех фиксируется только при ответе финальной операции
с публичной ссылкой. Ответ без ссылки — «проверьте площадку», автоматического
повтора нет. ID созданного черновика сохраняется отдельно до финальной отправки.

## Отправка и результаты

Задание запоминает список получателей и версии их личных подключений при
создании. Предпросмотр показывает эти площадки. При смене площадок или токена
для старого черновика требуется новое задание: старое подтверждение не может
отправить материал неожиданному получателю.

После согласования каждой площадке соответствует отдельная запись доставки.
Postmypost получает отдельную публикацию для каждого аккаунта — это позволяет
различать успех и ошибку получателей. Фотография загружается непосредственно
с диска в предоставленное API S3-хранилище, без API Authorization в запросе
хранилищу. После init → upload → complete бот ждёт file_id и только потом
передаёт текст и фото. Публикация создаётся со статусом 5 (ожидает отправки),
а не 4 (черновик). Неиспользованные фото при неудаче подготовки могут остаться
в хранилище сервиса.

Успешное создание записи Postmypost ещё не значит успех в соцсети. Бот проверяет
результат сразу после отправки и при открытии задания или `/status`. Фонового
планировщика и опроса нет. До подтверждения сервисом отображается «ожидает/
публикуется». Ссылку на пост ВК по ID сервиса бот не выдумывает: показывает
ID записи Postmypost и её статус. Подписка на вебхуки пока не реализована.

При частичном успехе показывается результат каждой площадки. Повторное нажатие
не отправляет материал ни успешным, ни ошибочным получателям. После тайм-аута
создания записи результат считается неизвестным; автоматического повтора POST
нет. После перезапуска сохраняются ID очереди для чтения статуса, незавершённые
отправки переходят в «проверьте площадку», а не начатые — в ошибку. Создание
нового задания после неизвестного результата допускается только после ручной
проверки соответствующей площадки на отсутствие дубля.

Ограничитель запросов учитывает пользователя подключения: upload — 10/мин,
создание — 10/мин, остальные запросы — 30/мин, окно 60 секунд. Лимиты могут
также расходоваться другими приложениями пользователя; 429 показывается как
ошибка, запись автоматически не создаётся повторно.

## Обновление и резервная копия

Перед обновлением остановите бота и сделайте SQLite backup. Миграции аддитивны:
старые проекты, участники, настройки и задания не удаляются. Прежние VK API и
браузерные адаптеры сохранены для старых подключений, но не предлагаются в новом
списке площадок. Добавление Postmypost/Дзена переводит проект на новую модель;
для неё создайте новые задания. Не переключайте рабочий проект на legacy-режим
во время отправки.

Сохраняйте вместе с базой `data/platforms.key` (права 600), `data/oauth.key`
при наличии legacy-подключений и материалы. Без `platforms.key` расшифровать
личные токены/сеансы после восстановления нельзя. Его отсутствие при наличии
зашифрованных данных приводит к ошибке, а не к автоматической замене ключа.
Удаление проекта удаляет его площадки и результаты доставки, но сохраняет
личные подключения пользователя для других проектов и не удаляет опубликованные
или уже запланированные материалы на внешних сервисах.

## Проверка

```sh
.venv/bin/python -m unittest discover -s tests -v
```

Тесты покрывают несколько получателей, личные токены разных владельцев,
согласование участником, выбор площадок и пагинацию, изменение токена/получателей,
отзыв доступа, частичный отказ, тайм-ауты и перезапуск без повторного POST.
Полный цикл Postmypost с загрузкой фото проверяется на локальном HTTP-сервере.
Сценарий Дзена проверяется с имитацией ответов editor API. Реальные отправки
в сервисы и списания по тарифу в рамках разработки не выполнялись.
