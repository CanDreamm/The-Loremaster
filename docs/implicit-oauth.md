# Пользовательский ключ через Implicit Flow

Адаптер `vk_implicit` получает пользовательский API-ключ через
`https://oauth.vk.com/authorize` с `response_type=token` и запрашивает
`wall,photos,groups,offline`. Используется ID собственного приложения.
Client secret для этого flow не требуется.

Основание: [официальный пример ВК](https://github.com/VKCOM/java-sdk-examples/blob/master/src/main/java/examples/user/UserAccessTokenProvider.java).
Пример использует Standalone-приложение. Поддержку flow и прав конкретным
приложением нужно подтвердить живым входом: код не выдаёт дополнительных прав.

## Включение на текущем сервере

HTTPS и маршрут callback уже должны вести к боту. Для текущего приложения
Redirect URL — `https://bot.itiscat.ru/oauth/vk/callback`, ID — `54825414`.
Используется собственный callback, не `blank.html`; возможность этого URI
зависит от настроек и разрешённого приложению flow.

Остановите ручной процесс через Ctrl+C. При установке от root выполните:

```sh
cd /opt/publikot
git pull --ff-only origin master
.venv/bin/python scripts/configure-oauth.py --provider vk_implicit
.venv/bin/python -m unittest discover -s tests -q
.venv/bin/python -m publikot
```

При установке с пользователем и службой `publikot` следуйте
[соответствующему варианту обновления](server-update.md); Python запускается
от пользователя `publikot`, после настройки запускается служба.

При старте проверьте строку `OAuth: приложение 54825414, режим vk_implicit`.
Если указан другой режим, проверьте каталог запуска и переменные окружения,
которые могут переопределять `.env.python`.
Получите **новую** ссылку через «Добавить сообщество» → «Выбрать сообщества ВК».
Для повторного подключения заданного проекта также доступно
«Подключение ВК» → «Авторизоваться в ВК».
В ней должны быть `oauth.vk.com/authorize` и `response_type=token`.
Прежние ссылки code flow для нового режима не подходят.

## Процесс

1. ВК получает согласие пользователя и возвращает ключ в fragment после `#`.
   Fragment не отправляется веб-серверу в HTTP-запросе.
2. Локальный скрипт callback считывает fragment и очищает адрес через
   `history.replaceState`, не показывая ключ на странице.
3. Ключ и одноразовый state отправляются JSON POST на тот же callback по HTTPS.
   Требуются точный Origin сайта, JSON и действующий state. Лимит тела — 8192 байта.
4. Сервер проверяет личность через `account.getProfileInfo`, wall/photos через
   `account.getAppPermissions`. Поле `user_id` из fragment не доказывает личность.
   При добавлении сообществ список загружается через `groups.get`, временный
   ключ шифруется, браузер переходит на `/oauth/vk/select` с Secure/HttpOnly cookie.
   Пользователь отмечает одно или несколько сообществ и подтверждает выбор.
5. Перед сохранением повторно проверяются доступ, права редактора/администратора
   через `groups.getById` и отсутствие отмены. Ключ шифруется существующим
   `data/oauth.key`. Новые проекты создаются только после подтверждения выбора.
6. В браузере и боте появляется результат без ключа. Публикация остаётся
   отдельным действием с подтверждением актуальной версии текста.

Ссылка действует 10 минут и расходуется один раз при POST. Проверяются повторы,
отзыв доступа, новая ссылка и отключение. Срок подключения берётся из выданного
`expires_in`; 0 означает отсутствие заявленного срока. Запрос offline не
гарантирует бессрочную выдачу, ВК может отозвать ключ раньше.

HTML использует локальный скрипт с CSP nonce; внешних ресурсов нет.
Access logs nginx и aiohttp для callback отключены, Referer не передаётся.
Ключи из query URL и cross-origin POST не принимаются. Не копируйте адрес
после входа в чат: fragment содержит ключ.

## nginx и диагностика

Используется `location /oauth/vk/`, проксируемый на `127.0.0.1:8081`;
он должен пропускать GET и POST для callback и `/oauth/vk/select`.
При обновлении замените прежний точный location callback этим префиксом,
сохранив настройки proxy и TLS: см. [шаблон nginx](../deploy/oauth-nginx.conf.example).

В режиме `vk_implicit` пустой GET callback возвращает HTTP **200**, HTML и
`X-Publikot-OAuth: 1`. Скрипт объяснит отсутствие результата входа.
В code flow пустой GET по-прежнему возвращает HTTP 400.

После подключения отдельно подтвердите тестовый текстовый пост, затем фото.
Отказ ВК до callback или неподдерживаемый flow требуют проверки типа/доступов
собственного приложения. Не переключайте на чужой App ID.
Ошибка возврата кода вместо ключа означает, что используется старая ссылка.
Ошибки проверок показывают метод и числовой код API; ключ при отказе не
сохраняется и не перезаписывает прежнее подключение.
При явном отказе `wall.post` задание получает статус ошибки, а пользователь —
метод и числовой код API. При потере связи после начала отправки результат
остаётся неизвестным: сначала нужна проверка стены, автоматического повтора нет.

Серверные тесты: `python -m unittest discover -s tests -q`.
JavaScript: `node tests/test_implicit_callback.mjs`. Node.js нужен только для
разработческих тестов; в работе скрипт исполняет браузер пользователя.
Локальные проверки не заменяют живую авторизацию собственного приложения.
`tests/test_publishing_flow.py` проходит полный сценарий от меню добавления
сообщества до HTTP-запроса `wall.post` через локальную имитацию ВК: ключ
проверяется настоящим кодом API-клиента, публикация выполняется настоящим кодом
публикатора. Проверяются новая версия текста, старое подтверждение, повторы
и явный отказ API. Этот тест не обращается к реальным аккаунтам.
