# Минимальный запуск: сообщество → задание → короткий текст

Интерфейс — личные сообщения сообщества бота ВК. `/start` или `/menu` открывает
главное меню. Старые команды сохранены, но основной сценарий обходится без них.

## Перед обновлением сервера

Сначала [определите способ установки](server-update.md#сначала-определите-способ-запуска).
Для root без службы используйте вариант А, для созданной службы с пользователем
`publikot` — вариант Б. Порядок: остановка текущего процесса, резервная копия,
обновление кода и зависимостей, тесты, запуск. Существующая база сохраняется;
таблица диалогов добавляется автоматически. Запускайте один экземпляр бота.

В `.env.python` должны быть настроены `VK_BOT_TOKEN`, `VK_BOT_GROUP_ID` и
`OWNER_VK_ID`. Для настоящей генерации укажите `YANDEX_API_KEY`, `YANDEX_FOLDER_ID`
и `DEMO_MODE=false`; у аккаунта Yandex должны быть доступ к модели и средства.
После изменения настроек перезапустите текущий процесс или службу. В демо-режиме бот показывает
задание вместо обращения к ИИ и не разрешает публикацию.

Для авторизации текущего приложения выполните в каталоге проекта
`.venv/bin/python scripts/configure-oauth.py` при установке от root, либо
`sudo -u publikot .venv/bin/python scripts/configure-oauth.py`, если этот
пользователь создан и владеет проектом. Скрипт запишет приложение
`54825414` и домен `https://bot.itiscat.ru`, сохранив секреты и выбранного
провайдера. Публичный HTTPS callback и разрешения приложения проверяются отдельно
по [oauth.md](oauth.md). Для получения текста OAuth не обязателен.

## Меню

- Главное меню: «Мои сообщества», «Управление доступом», «Помощь».
  Управление доступом видит только администратор.
- «Мои сообщества»: прежний список, выбор сообщества, пагинация и кнопка
  «Добавить сообщество». Добавление доступно всем допущенным пользователям.
- Управление доступом: «Разрешить доступ», «Запретить доступ», «Участники бота»,
  «Главное меню». Назначение проектов сохранено в административных командах.
- Сообщество: «Написать текст», «Мои задания», «Настройки проекта», «Назад»,
  «Главное меню». «Назад» возвращает в список сообществ.
- Настройки проекта: «Концепция», «Тон общения», «Правила для текста»,
  «Визуальный стиль», «Персонажи», «Назад».
- Каждый раздел настроек сначала показывает сохранённое состояние и кнопки
  «Добавить» и «Назад». Ввод начинается после «Добавить»; текст заменяет
  текущее значение, дефис очищает его. После сохранения снова виден раздел.
  Визуальный стиль и персонажи принимают строго по одному фото на раздел
  с необязательной подписью; следующее фото заменяет предыдущее.
- Фото-референс можно приложить к заданию публикации и описать, что с ним сделать.
  Оно необязательно, хранится в задании и автоматически не публикуется.
- Для каждой версии формируются промпты текста и изображения. Кнопка «Промпты»
  в предпросмотре показывает оба текста. Генератор изображений ещё не подключён;
  готовое фото можно добавить отдельно в предпросмотре.
- Во время ввода «Назад» возвращает в раздел без изменения данных; из раздела —
  в настройки проекта, из настроек — в меню сообщества.
- При успешном переходе по кнопке новый экран заменяет предыдущие сообщения
  бота: удаляются текстовые части и изображения, отправленные до этого перехода.
  Новые кнопки используют `callback`: нажатия не создают сообщений от пользователя.
  Введённые вручную тексты и фото остаются в личной переписке: сообщество
  не может удалить их из истории пользователя. ID исходящих сообщений записываются
  в SQLite, поэтому очистка работает и после перезапуска. Начните проверку
  новой версии с `/menu`, затем нажмите кнопку: сообщения старых версий,
  отправленные до появления учёта ID, автоматически не удаляются.
  Используется [messages.delete](https://github.com/VKCOM/vk-api-schema/blob/master/messages/methods.json)
  с `delete_for_all=1`. Если ВК отклоняет удаление, причина выводится в терминале;
  выполненный переход или публикация из-за этого не повторяются.
- Подключение ВК для существующего проекта доступно через `/connect`,
  `/connection`, `/disconnect`; смена ID — через `/vk`.
- Готовый текст: исправление, добавление/замена фото, отмена черновика,
  возвращение в меню. Для реального текста с заданным сообществом предлагается
  публикация; сервер проверяет ключ и требует нажатия кнопки подтверждения.

## Первый текст

1. Отправьте `/start` → «Мои сообщества» → «Добавить сообщество».
2. Нажмите «Выбрать сообщества ВК», войдите тем же аккаунтом и разрешите доступ
   приложению. Затем отметьте галочками свои сообщества и подтвердите выбор.
   Названия загрузятся автоматически; ID и ключи отправлять в чат не нужно.
   Для этого сценария необходимы рабочий OAuth и права приложения на API.
3. Вернитесь в «Мои сообщества», выберите нужное и нажмите «Написать текст».
   Для подготовки текста без OAuth администратор может создать проект через
   `/new Название` и `/vk ID`, затем выбрать его в меню.
4. Отправьте задание, например: «Напиши о новой кофейне. Открытие в субботу
   в 10:00. До 400 символов, без эмодзи». По умолчанию запрашивается до 500 символов;
   это инструкция модели, текст не обрезается автоматически.
5. Нажмите «Изменить текст» и отправьте замечание, если нужно. Старые кнопки
   перестают действовать после новой версии. Самостоятельно ничего не публикуется.
6. В следующий раз откройте «Мои сообщества» и выберите нужное кнопкой.

Кнопка возврата отменяет ожидание ввода. `/menu` сбрасывает любой диалог.
При перезапуске незавершённый диалог сохраняется; права и актуальность версии
повторно проверяются перед выполнением действия. Если участник пишет в проект,
доступ к которому отозван, бот отказывает.

## Проверка после установки

Проверьте добавление своего сообщества, возврат в список и повторный выбор,
настоящую генерацию текста, исправление и открытие черновика из «Мои задания».
Затем проверьте авторизацию и статус подключения. Реальный тест публикации
проводится отдельно в тестовом сообществе после подтверждения текста.
Локальные тесты не подтверждают доступность вашего сервера, оплату Yandex
или выдачу приложению разрешений ВК.
